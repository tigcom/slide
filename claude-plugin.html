Claude Code: Giới hạn

  • Claude Code nguyên bản (chưa cài plugin) đã tự: đọc/sửa file, chạy lệnh, tìm code, thao tác git.
  • Không phải chatbot copy-paste — nó đã là công cụ tự vận hành.
  • Nhưng tự nó vẫn còn 4 giới hạn — chưa bàn đến cách lấp.

Plugin là gì

  • Để lấp các khoảng trống trên, Claude được "mở rộng" — ta gọi chung là plugin.
  • "Plugin" hiểu theo nghĩa rộng: cơ chế mở rộng khả năng làm việc của Claude — bên trong có thể là một thành phần đơn lẻ, hoặc nhiều thành phần kết hợp.
  • Mỗi plugin nhắm một kiểu khoảng trống: phương pháp, hành động, tự kích hoạt, tổng hợp.

Phần 03 · Cơ chế hoạt động

Skills — làm thế nào?

  • Trả lời "làm việc này theo cách nào": đóng gói một phương pháp/quy trình để Claude thực hiện nhất quán.
  • Ví dụ: skill thiết kế giao diện quy định trình tự — mục đích → cấu trúc → bố cục → màu → chữ → component → responsive.
  • Biến "biết làm" thành "làm theo phương pháp chuẩn".
Claude + Plugin 2026
Phần 03 · Cơ chế hoạt động

MCP server — có thể làm gì?

  • Trả lời "Claude có thể thao tác gì với công cụ ngoài": chuẩn mở (Model Context Protocol) kết nối database, trình duyệt, API, filesystem.
  • Ví dụ: MCP server điều khiển trình duyệt thật — mở trang, click, nhập liệu, chụp ảnh.
  • Từ "suy luận, dự đoán" sang "quan sát, hành động thực tế".

Phần 03 · Cơ chế hoạt động

Hooks — khi nào tự động làm?

  • Trả lời "khi nào tự chạy": lệnh tự động kích hoạt khi một sự kiện xảy ra (trước/sau hành động).
  • Ví dụ: khi chuẩn bị commit, hook tự chạy quy trình review + test.
  • Biến từng bước thủ công thành quy trình tự động.
Claude + Plugin 2026
Phần 03 · Cơ chế hoạt động

Sub-agent — ai làm phần nào?

  • Trả lời "ai làm phần nào" và "cuối cùng đã làm gì": chia việc lớn cho các agent con, chạy song song rồi tổng hợp.
  • Ví dụ: 1 agent phân tích code, 1 agent kiểm tra frontend, 1 agent chạy test — gom thành báo cáo.
  • Giải quyết việc lớn + tổng hợp kết quả cuối phiên.
